## 1.（chk-prop）§1 批的空 `rgMbid` **不需要改 chk-prop**——照抄 c-107 的版本就能跑到標記 0

派工信說「若 chk-prop 因空 rgMbid 報錯，照 c-87／c-92 怎麼處理就怎麼改」。
**實查：不必改。** 逐行比對 `c92/chk-prop.mjs` 與 `c107/chk-prop.mjs`，兩份只差三處
（批號、`groups` 預設值、c-107 多的「掛名含非 ASCII 連字號」那道檢查，即第 186 條），
**兩份都沒有任何一行讀 `rgMbid`**——它檢查的是缺欄、曲風越界、年份、非 ASCII 連字號、
§5.6 例外欄位、線上池撞卡、跨組重複與跨批去重，`rgMbid` 從頭到尾不在清單裡。

**裁定：`batch-progress/c113/chk-prop.mjs` 從 c-107 原樣複製，只改批號與 `groups` 預設為 `['a']`，
不做其他修改。** 這樣 c-113 也保住了第 186 條那道掛名檢查（c-92 那份沒有）。
跑出來 **30 張、14 位、標記 0，跨批去重 64 批 2,938 張全數不撞**。

## 2.（第 187 條實證）知名定男在 MB 內部被拆成兩個藝人實體——《うたまーい》因此**不屬本批**

`artist?query=知名定男` 的 score 100 是 `cc35212d-2481-4a45-8e63-463bb13296c1`（名下 **0** 個 release-group）；
依第 187 條改查羅馬字 `artist?query=Sadao China`，score 100 回的是**另一個實體**
`d067afd6-29fa-447a-9dd0-3be9ded4f4b5`，名下有 1 筆 **《Utamaai》2005（`a7aa78e7-4ec9-4130-a99d-b26e58b73463`）**，
就是 2005 年リスペクト盤《うたまーい》。

**只查漢字掛名的話，這張會被誤判成「MB 查無」而收進 §1 批——那是半套，會讓 MBID 硬規則作廢。**
**裁定：《うたまーい》不收，列進下方「其實 MB 有建檔」清單；本批 14 位藝人每一位都跑過原文與羅馬字兩種寫法**，
逐筆寫進各卡的 `mbAbsenceProof.queries` 第一項。

## 3.（舉證）國立國會圖書館サーチ（NDL Search）當日本線 §1 的標準第二來源

§1 要件寫「≥2 個 HTTPS：唱片公司／官方發行頁／**館藏目錄**／Discogs release」。
本批的碟半數以上是 1970–90 年代沖繩在地小廠的盤，唱片公司官網早就不在了，Apple 也只有一半有數位。
**裁定：以 `https://ndlsearch.ndl.go.jp/books/<記錄 ID>` 的永久記錄頁當第二來源**，
用 `https://ndlsearch.ndl.go.jp/api/opensearch?title=<盤名>` 或 `?any=` 查，記錄頁帶出版者與著者欄，
可以逐筆對上廠牌與掛名。**30 張裡 21 張有 NDL 記錄、19 張有 Apple collectionId，每一張至少有兩個非 Discogs 或含 Discogs 的獨立來源。**

⚠ 用 `any=` 查短詞會被斷詞打爛（查「道うた」回一整頁アイヌ研究報告），**短盤名一律用 `title=`**。
⚠ Discogs 的**網頁**會 403（實測 30 個 release 頁全部 403），但 `api.discogs.com/releases/<id>` 全部 200——
403 是反爬蟲不是查無，`manualEvidenceUrls` 照樣填網頁網址（那是給人看的），存在性由 API 確認。

## 4.（掛名）りんけんバンド與ネーネーズ**維持片假名**——第 177 條壓過第 189 條的例外條

兩團都拿得出官方羅馬字名（Sony 盤面印 Rinken Band、廠牌名就叫 Rinken Records；
Discogs 的 Nenes anv 是 Nēnēs），照 08-11 裁定的例外條「完全無漢字就羅馬化」是可以改的。
**但第 177 條說掛名的取用順序是「先看池中、再看 MB credit」**，而池中已有
`りんけんバンド`（なんくる／チェレン 2 張）與 `ネーネーズ`（あしび／コザ dabasa／なーらび 3 張）。

**裁定：兩團一律沿用池中的片假名寫法**，羅馬字進 `queryAlias`。
改成羅馬字只會多製造兩組 `audits/pool-artist-name-splits.md` 要收拾的分裂；
ネーネーズ 那邊還會撞上 Apple 上同名的荷蘭 trance 團體 Nenes（artistId 257332454）。
**可逆**（只改 artist 欄）。

## 5.（盤名）登川誠仁《Spiritual Unity》改取日盤片假名《スピリチュアル ユニティ》

Discogs release 8278091 的標題是英文 `Spiritual Unity`。但**池中已有 Albert Ayler Trio《Spiritual Unity》
與 Albert Ayler《Spiritual Unity》兩張**（自由爵士正典），照 Discogs 寫會讓池中出現三張同名碟。

**裁定：取 NDL 與 Apple jp 都採用的片假名題名《スピリチュアル ユニティ》**
（NDL `R100000001-I22213001300088336`，出版者リスペクトレコード，作者登川 誠仁；Apple collectionId 308642524）。
這不是自創——是日本館藏目錄與日本店面共同的建檔名。英文名進 `queryAlias`。**可逆**（只改盤名欄）。

## 6.（盤名）Discogs 標題前後掛的破折號與括號一律去掉，只留主標與副標，用空白分隔

本批有五張的 Discogs 標題帶裝飾符號：
`誇 ー八重山の祝のうた`（U+30FC 片假名長音符）、`伝いやり - 風便り 唄便り -`、
`うちな～ゆんたく -沖縄の笑い芸-`、`彈 語やびら島うた  ~嘉手苅林昌の世界~`（兩個半形空格、且彈在前）、
`華ぬ遊び唄　松田弘一特集`（全形空白＋「特集」後綴）。

**裁定：全部改成「主標 空白 副標」**（`誇 八重山の祝のうた`、`伝いやり 風便り唄便り`、
`うちな～ゆんたく 沖縄の笑い芸`），原寫法進 `queryAlias`。
理由是 c-50 踩過的標題比對失準與第 186 條：**裝飾符號不是識別資訊，卻會讓摺疊比對整組偏掉**。
嘉手苅林昌那兩張改取 Apple 2014 年數位版的寫法（`語やびら島うた 彈 ~嘉手苅林昌の世界~`、
`飄 ~嘉手苅林昌の世界 その2~`），因為那與 collectionId 對得起來，封面反查會直接命中。

## 7.（形態）照屋林助《うちな～ゆんたく 沖縄の笑い芸》是漫芸盤，收，但要標記

這張 1981 年 CBS/Sony 25AG 765 是「沖縄の笑い芸」——三線伴奏的漫談與唄的混合體，
Discogs 的曲目列只有兩軌（LP 的 A／B 兩面各一整段），**不是一般意義的音樂專輯**。

**裁定：收。** 理由：照屋林助是ワタブーショー的創始者、りんけんバンド照屋林賢的父親，
這條線在池中只有下一代兩張、上一代零張；他 1996–98 年那三張《平成ワタブーショー》**MB 已建檔**，
本批能收的只剩這一張。**但 `risk` 明寫它是漫芸盤，簡介不得寫成音樂專輯**，
上架時若店主認為形態不合，撤掉只需刪一張卡單（可逆）。

## 8.（舉證門檻）「只有 Discogs 一個來源」的碟一律不收，寧可少收也不半套

§1 的代價本來就是舉證更重。本批查到七張 MB 確實查無、Discogs 也有實體條目，
**但 NDL 與 Apple 兩邊都找不到第二個來源**——這種只有單一來源的碟，
收了就等於把 §1 變成「查不到就宣告查無」的逃生門。**裁定：全部不收，逐筆記在下方未收清單**，
本機若能開沖繩縣立圖書館目錄或マルフク／ディスクアカバナー的發行目錄，應優先補這七張。

因此大工哲弘從原本規劃的 1976／1980 兩張黑膠改成 1997／1998／2001 三張 CD，
前川守賢從 1987 年的《遊び庭》改成 1998 年的《げんちゃんパラダイス》，
ネーネーズ從 1991 年首張《IKAWU》改成 1992 年的《YUNTA》——**都是為了湊齊兩個獨立來源而降低代表性，這是刻意的取捨。**

## 9.（形態）Discogs 藝人目錄的 `type: master` 與 `type: release` 要分開打端點

`/artists/<id>/releases` 回的清單裡，`type` 為 `master` 的項目**其 id 是 master id 不是 release id**。
第一輪抓詳情時直接把它們丟進 `/releases/<id>`，十二筆全部回了不相干的碟
（`1282796` 應是嘉手苅林昌《彈》，用 `/releases/` 打回的是 Heart《Dog & Butterfly》）。

**這是第 122 條「回了完全不相干的東西」在 Discogs 這一側的同形實例。**
**裁定：往後抓 Discogs 藝人目錄，一律先看 `type` 欄，master 走 `/masters/<id>` 與 `/masters/<id>/versions`，
release 才走 `/releases/<id>`。** 本批已依此重抓，全部三十張的廠牌、編號、年份、軌數都以正確端點覆核過。
