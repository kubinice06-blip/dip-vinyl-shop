# 研究層補充：Bandcamp「有鼓」名單第三輪（ml74–81、md44–45 共用；2026-11-06）

讀完 `RES-DISPATCH.md` 後再讀這份。這一輪的卡**都是前兩輪因「有拍推進」被汰、或被舞池／嘻哈標籤先篩掉的**。店主：「有些要死不活的音樂也會有鼓推進」「全都上架吧」。

1. **聲音條要寫清楚鼓是哪一種**（facts 至少一條、notes 一句結論）：
   - **慢拖無力型**：慢（約 ≤95 BPM 或半速）、鬆、懶、拖拍、dusty 取樣鼓、trip-hop 慢 breakbeat、boom bap 慢拍、dub 一滴一滴的 one-drop——**照 BRIEF 仍是靜（x 2–2.9），不是汰的理由**。
   - **舞池推進型**：四拍底鼓、house／techno／breakbeat 跳舞律動、psytrance 式持續推進、明顯中快速（約 ≥110 BPM 且讓人想動）。
   - **攻擊型**：失真牆、嘶吼、音壓貼臉。
   - **無鼓／鼓很少**。
   判不出來就寫「判不出」，**不要因為有鼓就寫建議汰**。只有確定是舞池推進型或攻擊型才在 notes 寫「moodGuess 存疑：舞池推進／攻擊型」。判輕、判冷也照寫（「moodGuess 存疑：判輕／判冷」），但主線這輪不因判輕判冷汰，只用來給評分參考。
2. **沿用前次研究稿**：卡單 `curatorRisk` 寫「前次理由：mlXX…」而且 `rulings.md` 主線策展段列為「沿用前次研究稿」的卡，原稿在 `batch-progress/add-20261106-<批>/dropped-research.json`（用 key 的藝人＋盤名找）。**整筆複製過來（key 改成本批卡單的 key，逐字照抄卡單）**，facts 不足 8 條或聲音條沒講清楚鼓的種類才補，不要整張重查；notes 開頭寫「沿用 <批> 研究稿；補 N 條」。前次的「建議汰」改寫成本輪判斷。
3. 標籤含 house／techno／edm／trance／breaks 的卡（主線留給你判）：查廠牌文案、樂評、Beatport／Apple 曲目 BPM，判是不是舞池推進型。
4. 前兩輪經驗：Bandcamp 自訂網域常 303 迴圈，改用 `https://<帳號>.bandcamp.com/...` 或 Wayback（`https://web.archive.org/web/2024/<url>`）取 ld+json；Apple `itunes.apple.com/lookup?id=<collectionId>&entity=song` 可拿曲長與曲數。
